INSUREFLOWAI 2.0 — LIFE VERTICAL PATCH NOTES
Pushed: 2026-09-06 (branch: main)

WHAT THIS ADDS
Russell-method 2-minute life insurance fact-find vertical, running in
parallel with the existing commercial pipeline. Small-biz owners
(occupation sourced from HasData Google Maps Categories) → Vapi life
fact-find call → Brevo SMS + email with InsureMeNow close link.

NEW FILES
- src/routes-life.js    Life endpoints (leads, scrape, factfind, stats, test call)
- src/lib/life.js       Life brain: openers, fact-find extraction,
                        completeness scoring, qualification, Brevo
                        follow-up, HasData scraper

PATCHED FILES
- src/config.js         + VAPI_LIFE_ASSISTANT_ID, INSUREMENOW_LINK,
                        HASDATA_API_KEY env vars
- src/lib/vapi.js       makeCall() branches: life leads use
                        VAPI_LIFE_ASSISTANT_ID + life variables;
                        exports isLifeLead()
- src/workers/callWorker.js  Webhook branches life leads to
                        handleLifeOutcome() (fact-find persistence +
                        InsureMeNow follow-up + Dave task) instead of
                        the commercial Account/Opportunity promotion
- src/server.js         Mounts routes-life (/api/life/*), startup log

DATABASE (REQUIRED BEFORE DEPLOY — see below)
- prisma/schema.prisma  + LifeFactFind model (one per lead):
                        age, tobacco, healthFlags, coverageGoal,
                        dependents, hasSpouse, existingCoverage,
                        monthlyBudget, email, score (0-100), source

QUALIFICATION RULE (life)
Qualified = disposition in (booked, interested) AND fact-find
score >= 50. Score weights: age 25, tobacco 20, coverageGoal 25,
healthFlags 10, existingCoverage 10, budget 5, dependents 5.

POST /api/life/scrape             HasData occupation scrape → leads → calls
                                  { category, city, state, limit, autoCall }
                                  [admin key required]
POST /api/life/factfind/:leadId   Manual fact-find entry/edit [admin]
GET  /api/life/factfinds          List fact-finds (?minScore=) [admin]
POST /api/life/factfind/:leadId/resend  Re-send InsureMeNow link [admin]
GET  /api/life/test-call/:phone   Browser test call (?force=true) [admin]
GET  /api/life/stats              Life funnel numbers [admin]

ANNUITY VERTICAL PATCH NOTES
Pushed: 2026-09-15 (branch: main)

WHAT THIS ADDS
A third pipeline — annuity — for CONSUMER retiree prospecting, built
compliance-first (TCPA). Purchased consumer lists are imported, DNC
screened, and routed to an email-first nurture drip. Vapi (AI voice)
is deliberately gated OFF for consumer leads until consent exists.

DECISIONS LOGGED (the "memory" for this vertical)
- Data source for annuity prospects = CONSUMER LIST BROKERS
  (Data Axle, LeadsPlease) filtered age 55/60+, homeowner, modeled
  net worth. NOT HasData (that's businesses) and NOT Apollo (B2B).
- First test = a $100-200, ~1,000-record Data Axle list in MI
  (homeowners, 60+, $100k+ assets) before any larger spend.
- Compliance lane: consumer annuity = email/mail + inbound callbacks.
  AI-voice cold call to a consumer cell w/o written consent = TCPA
  liability ($500-1,500/call). So autoCall is FORCED OFF on imports.
- Agent-recruiting ("Automator+") feature was DISCUSSED and DEFERRED —
  not part of the current model.

NEW FILES
- src/routes-annuity.js       Annuity endpoints (import, leads, stats)
- sequences/annuity_drip_v1.json  5-touch email nurture drip

PATCHED FILES
- src/server.js               Mounts attachAnnuityRoutes, startup log line

DATABASE
- No migration. Reuses leads.vertical='annuity', native age column,
  and industry column to carry the asset bracket (queryable).

ENDPOINTS (all admin-key)
POST /api/annuity/import      Bulk consumer CSV/JSON import + drip enroll
POST /api/annuity/leads       Single lead; consent=true -> Vapi, else drip
GET  /api/annuity/stats       Funnel counts + scored top prospects

COMPLIANCE NOTES
- Import path hard-blocks any phone/email already on internal DNC.
- Sequence engine re-checks DNC before every touch; STOP kills instantly.
- SMS steps still require consent per the compliance engine; early drip
  steps are email-only by design.
